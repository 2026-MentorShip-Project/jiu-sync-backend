## add-event-created-email / `apps/notifications/tests.py` 從未被 pytest 收集，9 則既有測試實際上從沒跑過

- 發生了什麼：`pyproject.toml` 的 `[tool.pytest.ini_options]` 設定 `python_files = ["test_*.py"]`，但 `apps/notifications` 底下既有的通知信測試檔案名叫 `tests.py`（不符合 `test_*.py` pattern），導致 `send_event_finalized_email`/`send_event_cancelled_email`/`send_event_reopened_email` 那 9 則既有測試自這個檔案存在以來就從沒被 `uv run pytest` 實際收集執行過（`pytest --collect-only apps/notifications/` 回報 `no tests collected`），全套 `pytest -q` 的通過數字（232 passed）完全不包含這個檔案。
- 怎麼發現的：照 tasks.md 1.1 要求，把 `send_event_created_email` 的新測試依文件建議寫進 `apps/notifications/tests/test_tasks.py`，準備跑 RED 確認時才注意到既有 `apps/notifications/tests.py` 用單一檔案（非 `tests/` package），且檔名不符合收集 pattern，先前的「9 passed」從沒真的在 CI/本機驗證鏈上發生過。
- 怎麼處理的：把 `apps/notifications/tests.py` 遷移成套件形式 `apps/notifications/tests/__init__.py` + `apps/notifications/tests/test_tasks.py`（`git mv` 保留歷史），修正檔內相對匯入（`from .tasks` → `from ..tasks`），確認既有 9 則測試在新路徑下全部收集且通過，再依 tasks.md 補上 `send_event_created_email` 的新測試。修正後全套 `pytest -q` 從 232 passed 變成 247 passed（9 則既有 + 4 則新增 notifications 測試、2 則新增 events 測試）。這不是這次 change 的 design.md 範圍內的決策，但不修就無法讓 tasks.md 1.1 要求的 RED/GREEN 驗證產生意義，故一併處理。

## add-comment-rate-limit / `_try_acquire_comment_rate_limit_lock` 只捕捉 `RedisError`，設定錯誤的 `COMMENT_RATE_LIMIT_REDIS_URL` 會讓留言全面 500，違反 D7 fail-open

- 發生了什麼：task 3.2 的 `/code-review` 自審抓到，`redis.Redis.from_url()` 對不合法的 URL scheme（例如 `COMMENT_RATE_LIMIT_REDIS_URL` 打錯字、漏打 `redis://` 前綴）拋的是 `ValueError`，不是 `redis.exceptions.RedisError`；原本的 `except redis.exceptions.RedisError:` 只涵蓋連線類例外，設定錯誤會讓例外直接往上炸穿整個 `post()`，每個留言請求都變成 500——完全違反 design.md D7 明講的「不應該因為 Redis 問題拖垮核心的留言功能」。
- 怎麼發現的：`/code-review` 自審 forked agent 直接實測 `redis.Redis.from_url('not-a-valid-url')` 確認拋的是 `ValueError`，指出這條分支沒被涵蓋；同時另外指出每次請求都重新建立 `redis.Redis.from_url()` client（沒有重用 connection pool）是熱路徑上的效能浪費。
- 怎麼處理的：補一則新測試 `test_comment_rate_limit_fails_open_when_redis_url_is_malformed`（`apps/events/tests/test_views.py`），先用只捕捉 `RedisError` 的舊版程式碼確認 RED（真的拋 `ValueError` 500），再把 `except` 改成 `except (redis.exceptions.RedisError, ValueError):` 確認轉綠；同時把 Redis client 改成模組層級快取（`_get_comment_rate_limit_redis_client()`，依 `settings.COMMENT_RATE_LIMIT_REDIS_URL` 是否變動決定要不要重建，確保 `override_settings` 在測試裡仍然生效），解決第二點效能問題。全套 `pytest -q` 從 265 passed 變成 266 passed。
