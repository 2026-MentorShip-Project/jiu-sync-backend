## add-observability-stack / task 2.2 部署驗證時 nginx 的 /metrics 規則被誤還原、驗證指令無法執行

- 發生了什麼:提供給使用者的 nginx 步驟把「回滾指令」與一般步驟寫在同一則訊息,使用者連同回滾一起執行,`/metrics` 的 nginx 404 被還原掉;另外給的 python one-liner 括號有誤,且長指令經 SSM 貼上被終端機斷行、heredoc 結束標記因複製帶入的縮排失效。
- 怎麼發現的:外部 `/metrics` 回 Django JSON 404 而不是 nginx HTML 404;EC2 上出現 `SyntaxError`、`Too few arguments`、heredoc 卡在 `>`。
- 怎麼處理的:Django token 檢查期間仍有效(未洩漏);改用一行一個短指令(變數 + 暫存檔、`sed -i` 插入規則、`diff` 對備份)重新加回並驗證。之後給 SSM 手動步驟:每行保持短、不用 heredoc/多行 python、回滾指令與執行步驟分開標示「出事才執行」。


## add-observability-stack / task 3.1:cadvisor 需要 privileged 與 containerd.sock,超出 D8 接受的風險

- 發生了什麼:Alloy v1.20.1 的 `prometheus.exporter.cadvisor` 只掛 D8 的 `:ro` 掛載 + docker.sock 時,docker container factory 註冊失敗(`unable to create containerd client ... /run/containerd/containerd.sock`),拿不到任何 container 的 metrics;Grafana 官方文件也寫在 Docker 內執行需要 privileged 並掛 `/sys`、`/var/run`。
- 怎麼發現的:動手寫測試前以 docker 跑探測設定(非 privileged/掛 containerd.sock/privileged 三種組合)檢查 Alloy log 與 component metrics;unix exporter 在 D8 掛載下正常。
- 怎麼處理的:未寫任何程式碼或測試(repo 停在 1fef5ec 的穩定狀態),回報待使用者決定是否放寬 D8(privileged、`/run/containerd/containerd.sock`、`/sys:/sys`)或改用其他 container metrics 來源,需走 `opsx:update`。
