## add-observability-stack / task 4.3 code-review 抓到登入失敗 log 會帶出 token 原文

- 發生了什麼:`GoogleLoginView` 的登入失敗 warning 直接記錄 `GoogleTokenError` 訊息;google-auth 對格式錯誤的 token 會拋 `Wrong number of segments in token: b'<token>'`,token 原文進 log,且非 `eyJ` 開頭時 Alloy 的 JWT 遮蔽規則擋不到。此問題在改 JSON log 前就存在(經 `lastResort` 印到 stderr),design.md D11 原本未涵蓋。
- 怎麼發現的:task 4.3 實作後的 code-review(獨立 reviewer agent)標為風險,再以本機 google-auth 實測 `jwt.decode('abc.def')` 確認訊息含 token。
- 怎麼處理的:先補測試(RED)再改為只記例外類型名稱;寫回 design.md D11。

## add-observability-stack / task 4.3 Celery worker 的 stdout 重導會破壞 JSON log

- 發生了什麼:Celery worker 預設 `worker_redirect_stdouts=True`,`StdoutStreamHandler` 寫進 LoggingProxy 後,通知信 task 的 JSON 被加上 `[... WARNING/ForkPoolWorker-n]` 前綴,Loki `| json` 無法解析;D11 原本未預期。
- 怎麼發現的:實作後檢查 worker 執行路徑時推論,補測試後以本機 redis + 真的 worker 實測確認。
- 怎麼處理的:設 `CELERY_WORKER_REDIRECT_STDOUTS = False`(先寫測試 RED),實測 worker 輸出為純 JSON 一行;寫回 design.md D11。
