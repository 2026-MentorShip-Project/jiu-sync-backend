- 發生了什麼:tasks.md 1.1 寫 ②③④⑤ 為邊界守護、修正前後皆應通過,但 ⑤(naive `now` → `ValueError`)在修正前為 FAIL——舊碼 `now.date()` 對 naive datetime 不會報錯,會默默回傳 `finalized_past`/`finalized_upcoming`,正是 design.md D2 要防的行為。

## add-pgbouncer-and-celery-worker / task 2.1:design.md D4 Q6 只寫 `KILL`,實測 `KILL` 後資料庫維持暫停

- 發生了什麼:PgBouncer 的 `KILL <db>` 切斷連線後,該資料庫在 PgBouncer 內維持暫停狀態,新連線會卡住直到 `RESUME`;只照 design.md 下 `KILL`,下一次 pytest 經 PgBouncer 連 `test_jiu_sync` 會卡到逾時。
- 怎麼發現的:實作 ⑤ 前先以 psycopg 對本機 PgBouncer 探測 `KILL` 行為(`KILL "jiu_sync"` 後 `connect_timeout=3` 重連逾時;`RESUME` 後恢復;對未暫停的資料庫再 `RESUME` 回 `is not paused`)。
- 怎麼處理的:屬 design 既定機制的操作細節(非新的一致性/併發決策),實作為 `KILL` 後立即 `RESUME`、任一失敗皆拋例外,測試涵蓋;於 tasks.md 2.1 結果註明,design.md D4 措辭待使用者決定是否走 `opsx:update` 補上 `RESUME`。
