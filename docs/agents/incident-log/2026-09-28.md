## add-ai-restaurant-recommendation / task 1B code-review 抓到 JsonFormatter 會輸出不合法 JSON(NaN/Infinity),且 pytest 9 的 caplog 行為與預期不同

- 發生了什麼:`json.dumps` 預設 `allow_nan=True`,`cost_usd` 等欄位若為 `NaN`/`Infinity`(含 `Decimal("NaN")`)會輸出非標準 JSON,Loki `| json` 解析失敗;另外 1B.1 原本假設 `propagate: False` 時 caplog 抓不到 `apps.recommendations`,但 pytest 9.1 會把 caplog handler 也掛到該 logger,「不傳到 root」的測試改為直接在 root 掛 handler 驗證;`ext://sys.stdout` 會綁到 pytest 的全域 capture 檔,改用每次 emit 取當下 `sys.stdout` 的 `StdoutStreamHandler`。
- 怎麼發現的:`/mattpocock-skills:code-review` 兩個子審查都指出 NaN 問題並實測確認;caplog/stdout 行為是跑 1B.1 測試時以 probe 印出 logger handlers 確認。
- 怎麼處理的:先補 NaN/Infinity→null 與「序列化失敗改輸出含 `format_error` 的最小 JSON 行」兩則測試確認 RED 再修;`disable_existing_loggers` 的驗證改在子行程跑 `django.setup()`,避免測試內重跑 `dictConfig` 汙染全域 logging。後續 section 2 可直接用 caplog 驗 `apps.recommendations` 的 record。`pytest -q` 331 passed。
