## MODIFIED Requirements

### Requirement: Session 刷新
系統 SHALL 讓主揪的瀏覽器自動附帶其有效、未被撤銷的刷新憑證來換發新的存取憑證，且不需重新走 Google 登入；系統 SHALL 拒絕已過期或已撤銷的刷新憑證。刷新憑證 SHALL NOT 透過任何客戶端程式碼可讀取的管道傳遞（例如不得出現在 API 回應的 body 中），只能由瀏覽器以網頁程式碼無法存取的方式自動攜帶。

#### Scenario: 有效的刷新憑證換得新的存取憑證
- **WHEN** 主揪的瀏覽器自動附帶一個尚未過期、也未被撤銷的刷新憑證
- **THEN** 系統核發一個新的存取憑證

#### Scenario: 已撤銷或過期的刷新憑證被拒絕
- **WHEN** 主揪的瀏覽器附帶一個已過期、或已被撤銷（例如因登出）的刷新憑證
- **THEN** 系統拒絕該請求，且不核發新的存取憑證

#### Scenario: 刷新憑證對前端程式碼不可讀取
- **WHEN** 主揪成功登入，或成功換發新的存取憑證
- **THEN** 刷新憑證只存在於網頁 JavaScript 無法讀取的瀏覽器儲存機制中，不會出現在任何 API 回應的 body 裡

### Requirement: 登出撤銷 Session
系統 SHALL 讓主揪透過登出動作撤銷其刷新憑證來結束 session；該憑證由瀏覽器自動附帶，登出請求本身不需要客戶端程式碼提供憑證值。撤銷後，該刷新憑證 SHALL NOT 再被用來取得新的存取憑證，且瀏覽器端 SHALL 不再保留這個已失效的憑證。

#### Scenario: 登出使後續刷新失效
- **WHEN** 已登入的主揪執行登出
- **THEN** 其刷新憑證被撤銷，之後任何用它換發新存取憑證的嘗試都會被拒絕

#### Scenario: 不得撤銷他人的刷新憑證
- **WHEN** 已登入的主揪嘗試登出時，瀏覽器附帶的刷新憑證其所屬對象並非發起這次登出請求的主揪本人
- **THEN** 系統拒絕這次登出請求，不撤銷該刷新憑證

#### Scenario: 登出後瀏覽器不再保留刷新憑證
- **WHEN** 主揪登出成功
- **THEN** 瀏覽器不再保留可用的刷新憑證，後續請求不會再自動附帶任何刷新憑證
